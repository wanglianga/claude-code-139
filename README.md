# 社区共享停车 · 错停申诉、收益分账与夜间调度平台

面向社区夜间共享车位的一体化平台：业主发布闲置车位 → 外来车主预约 → 道闸识别/导航/入场 → 夜间异常调度 → 错停申诉责任判定 → 离场结算 → 收益合并分账 → 全链路追溯。

技术栈：**React 18 + Vite + TypeScript** ｜ **NestJS 10 + TypeORM + Passport/JWT** ｜ **PostgreSQL 15**，Docker Compose 一键启动。

---

## 一、一键启动（Docker Compose）

```bash
cd 139-b
docker compose up --build
```

| 服务 | 地址 | 说明 |
| --- | --- | --- |
| 前端（三端门户） | http://localhost:8080 | Nginx 托管 SPA，并反代 `/api` |
| 后端 API | http://localhost:3000/api | NestJS |
| PostgreSQL | localhost:5432 | parking / parking / shared_parking |

后端容器启动时会通过 `SEED_ON_BOOT=true` **自动播种演示账号与数据**（小区「朝阳景苑」、3 个已审核车位与当晚/明晚共享时段、优惠券）。重置演示数据只需 `docker compose restart backend`（会重新播种）。

> 前端为全栈工程的一部分，故按约定不额外提供 Swagger UI；接口可直接通过前端或下文 curl/脚本验证。

## 二、本地开发启动（不用 Docker）

需要 Node.js 20+ 与 PostgreSQL 14+。

```bash
# 1. 准备数据库
createdb shared_parking
#    或：psql -c "CREATE USER parking WITH PASSWORD 'parking';" -c "CREATE DATABASE shared_parking OWNER parking;"

# 2. 后端（TypeORM synchronize 自动建表）
cd backend
npm install
export DB_HOST=127.0.0.1 DB_PORT=5432 DB_USER=parking DB_PASSWORD=parking DB_NAME=shared_parking
npm run seed          # 播种演示数据（幂等，会重建演示数据）
npm run start:dev     # http://localhost:3000/api

# 3. 前端（新终端）
cd frontend
npm install
npm run dev           # http://localhost:5173 （/api 已代理到 3000）
```

环境变量（后端）：`DB_HOST / DB_PORT / DB_USER / DB_PASSWORD / DB_NAME / JWT_SECRET / PORT / SEED_ON_BOOT`。

## 四、业务能力对照

**车位发布与预约**
- 登记产权证号、可共享时段（可跨午夜）、靠近/本身是充电桩、是否允许访客、月租车优先规则（非月租仅可提前 24h 下单）、物业审核状态、导航引导。
- 时段重叠冲突校验；燃油车禁止预约充电车位；业主提前回家后该时段不再放出。

**入场—离场绑定同一笔停车服务**
- 道闸 ANPR 车牌识别（含置信度）、识别失败自动开异常单且不抬杆、物业人工放行留痕（操作员/核验车牌/备注）、入场即下发导航路线、离场即时结算（夜间封顶、超时 1.5 倍、优惠券）。

**夜间七类异常与调度**
- 业主临时回家（自动挪车通知 + 自动改派同小区空位，无空位则清退待结算）、访客超时、陌生车辆占位（巡查自动开单 + ¥50 追缴）、道闸识别失败、地库信号差、燃油车占充电位、物业人工放行。
- 改派时旧会话强制关闭并按实际停放立即结算，新车位重新入场，形成可追溯的两笔服务。

**错停申诉责任判定引擎**（`backend/src/common/liability.ts`，纯规则可单测）
- 汇总六类证据：车牌识别、预约记录、现场照片、道闸日志、业主回家时间、物业巡查记录。
- 输出责任归属（车主/业主/平台导航/物业/陌生车）、车主承担比例、信用扣分、完整证据推理链；物业可人工改判（留痕）。
- 费用处置：挪车通知宽限期与迟延违约金、超时费、给业主的补偿、异常补偿、退款/少缴追缴、信用影响。

**收益分账**（按小区 + 夜间日期合并清算，幂等可重算）
- 业主收益、物业服务费（8%）、平台抽成（12%）、优惠券抵扣（平台承担）、退款、异常补偿（按责任方扣减）、陌生占位违约金（平台 60% / 物业 40%）。
- 每笔明细解释**这一段时间由谁使用、谁支付、谁违约**；满足资金恒等式：`业主 + 物业 + 平台 = 车主实付`。

**全链路追溯**
- `audit_logs` 统一记录车位发布、审核、预约、入场、异常、挪车、调度、离场、申诉、分账；`/api/trace/spots/:id/timeline` 给出同一车位预约 vs 实际占用（含计费）的时间线。

## 五、验证方式

### 1. 自动化单元测试（计费与责任引擎）

```bash
cd backend && npm test
```

覆盖：夜间封顶、超时 1.5 倍、挪车宽限/迟延违约金、业主提前回家补偿、混合责任 50% 分摊、优惠券抵扣、陌生占位违约金；以及 8 个责任判定场景（无责/仅超时/业主回家/陌生占位/车主错停含燃油占充电位/平台改派/物业误引/信号差部分责任）。

### 2. 端到端夜间全流程（真实 HTTP + PostgreSQL）

先启动后端并播种，然后：

```bash
cd backend && bash e2e.sh
```

脚本自动完成同晚多车的完整剧本（所有时间按 UTC 模拟，便于复现）：

1. 业主发布新车位 D-009（产权/月租优先登记）→ 物业审核通过；再发布一个资料不全的车位被驳回。
2. 三笔夜租预约；重叠时段预约被拦截。
3. 京A12345 正常识别入场；京C66666 识别失败自动开单后物业人工放行（指引不清）。
4. 京D77777 到 D-009 发现被京C66666 占用：上报异常 → 巡查取证 → 挪车通知（19:15）→ 物业取消错停预约并把京D77777 调度改派至 C-030。
5. 业主 22:00 临时回家：自动通知京A12345 挪车，系统改派至充电空位 B-026；登记地库信号差工单。
6. 京C66666 20:45 离场（超宽限 75 分钟）→ 基础 ¥9.5 + 挪车违约 ¥15。
7. 京D77777、京A12345 分别离场：夜停封顶、超时费、优惠券抵扣（京A12345 券后实付 ¥28）。
8. 对陌生占位车追缴 ¥50。
9. 三起申诉：物业误引（成立，退 ¥23）、平台调度（成立，目标单退 ¥8）、信号差超时（部分成立 50%，退 ¥9，扣信用分）。
10. 当晚合并清算并校验资金恒等式。
11. D-009 车位时间线：预约车是京D77777（被调度），实际占用是错停车京C66666。
12. 全链路审计日志 + 道闸日志留痕。

### 3. 界面手工验证（推荐路径）

- 用 `owner` 登录 → 发布车位/时段 → 用 `property` 在「车位审核」通过。
- 用 `driver` 登录 → 预约（试重叠/非月租 24h 限制）→ 模拟入场/离场。
- 用 `property` 在「道闸台」输入脏车牌制造识别失败并人工放行；在「夜间异常与调度」登记异常、巡查、发挪车通知、改派、追缴。
- 用 `driver` 提交申诉 → 用 `property` 在「申诉裁决」查看证据链、可人工改判并确认。
- 物业「分账清算」按日期执行，查看 KPI、资金恒等式校验与逐段占用解释；「追溯中心」查看车位时间线与审计流。

## 七、说明与边界

- 演示工程使用 TypeORM `synchronize: true` 自动建表；生产环境应改为迁移文件。
- 支付、短信、ANPR 抓拍均为服务内模拟（离场即记账、通知即落库），但时间、金额、证据与状态全部持久化并参与结算。
- 时间统一存 UTC；前端时间输入按 UTC 语义解释，界面均标注 UTC。
